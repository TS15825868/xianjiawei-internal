# 仙加味 AI × IP × 自動化營運 SOP

版本：2026-10-07-v1  
狀態：正式總控規範  
適用：官網、LINE OA、ERP／貼文中心、社群、GitHub、自動化

## 1. 最高原則
資料正確｜圖文一致｜品牌一致｜功能正常｜正式可上線。新版正確資料優先於舊版資料；守門員用來阻止錯誤，不得阻止新版正確更新。

## 2. 權威順序
1. 使用者目前最新明確指示
2. 專案最新正式檔案、圖片、程式與資料
3. 三套正式 GitHub main 最新有效版本
4. 較新的專案紀錄
5. 已確認正式規格
6. 舊資料

## 3. 品牌 IP
公開主品牌固定「仙加味」；定位「現代漢方生活品牌」；標語「補養，是一種節奏。」公開內容不得顯示「台興山產」。小老闆與小鹿、小烏龜依正式角色規格；產品只使用正式實物外觀，不得由 AI 重畫包裝。

## 4. 產品母資料
ERP 的 config/official-products.json 與官網正式產品母資料共同構成目前產品權威。對外產品、規格、成分、圖片、交期不得由各平台自行發明。價格與促銷屬易變資料，發布前必須使用最新確認版本。ERP 可保留合法有效的內部、歷史與暫緩資料，不因對外隱藏而刪除。

## 5. AI 內容流程
題材／需求 → 重複檢查 → 文案草稿 → 品牌檢查 → 產品／規格檢查 → 法規檢查 → 情境與圖片規格 → 圖文一致檢查 → 待審核 → 使用者人工通過 → 排程或立即發布。

AI 自動檢查通過不等於人工核准。任何新文案、圖片、重新生成或實質修改均不得自行把狀態改為 approved。

## 6. AI 圖片與影片
生成式 AI 主要處理場景、角色動作與輔助視覺。產品貼文採「無產品場景生成 → 正式產品原圖自然合成」。禁止 AI 重畫、補畫、猜測產品包裝、標籤、瓶型、袋型、盒型與比例。生成圖有錯誤文字、台興山產、假產品、拼貼感或角色錯誤時直接不合格。

## 7. 風險分級
- 自動可執行：讀取、比對、格式檢查、重複檢查、規格檢查、法規字詞初篩、圖片完整性檢查、建立待審核草稿。
- 必須人工核准：公開貼文核准、排程前最終內容、立即發布前最終內容、重新生成後內容。
- 額外確認：重大不可逆刪除、金流、法律承諾、重大方案取捨或缺少必要資訊。

## 8. 發布狀態
draft → pending_review → approved → scheduled／published。
重新生成或修改文案／圖片後，舊核准失效並回 pending_review。立即發布不得被固定排程卡住，但仍必須先有人工作業核准。

## 9. 三系統同步
官網負責公開品牌、產品、FAQ、SEO／GEO／AIO；LINE OA 負責諮詢、產品選擇、試喝、下單與售後導流；ERP／貼文中心負責內部資料、內容生產、審核、排程與營運。公開產品基礎資料必須一致，ERP 可擁有更多內部欄位。

## 10. GitHub 與部署
修改前先讀正式 main。不得用舊 ZIP 覆蓋較新 GitHub。修正採根因處理並巡檢同類問題。只有 GitHub 實際成功回傳才稱 Commit／Push；只有正式平台實際部署成功並完成 live 驗收才稱已部署。

## 11. 守門
守門依「目前最新權威」判斷，不鎖死舊版本號、舊價格、舊圖片、舊文案或舊規格。最低安全檢查始終保留。完整阻擋守門只在目前正式權威與實際功能驗收完成後恢復。

## 12. 錯誤修復 SOP
發現問題 → 判斷根因 → 搜尋同類問題 → 全面修正 → 程式／資料檢查 → 桌機／手機與相關平台驗證 → GitHub 更新 → 正式部署 → live 驗收。不得只遮住單一畫面。

## 13. AI 搜尋曝光
SEO、GEO、AIO 共用正式品牌與產品母資料。AI 可讀資料不得與顧客頁、LINE OA 或 ERP 的正式公開資料互相衝突；更新產品母資料後應執行跨系統一致性檢查。

## 14. 總控來源
機器可讀入口：config/ai-ip-ops-authority.json。
既有細項規則繼續由該入口列出的正式檔案管理；本文件負責總流程與衝突裁決，不複製取代每一份細項設定。
