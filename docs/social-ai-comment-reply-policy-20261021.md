# 仙加味｜智慧社群留言與客服 AI 正式規格

版本：2026-10-21
狀態：**規格已建立；尚未完成 Meta 授權、實際留言讀取與端到端驗收；禁止宣稱已啟用無人值守自動回覆。**

## 範圍與來源
- Facebook 粉專、Instagram、Threads 貼文留言及回覆；LINE OA 與官網客服可共用回覆判斷規則，但不得取代各平台原有正式 webhook。
- 優先使用現有 Meta 官方權限、現有 Render Free n8n、Cloudflare 與 GitHub，不新增付費資源。Windsor.ai Free 目前遇到試用帳號數上限，不能以付費升級作為必要前提。
- 只有讀取到正式平台帳號、留言 ID、完整對話脈絡與可用回覆權限，才允許進入自動化驗收。

## 回覆決策流程
1. 識別平台、品牌帳號、貼文 ID、留言 ID、父留言、對話串及時間；確認留言屬於仙加味正式帳號。
2. 讀取同一串對話的歷史：客戶先前提問、品牌先前回覆、客戶最新追問與已處理狀態。
3. 對每則新留言分類：產品資訊、價格／訂購、使用／保存、品牌故事、稱讚／感謝、單純表情、客訴／售後、合作、醫療功效、垃圾／騷擾、其他。
4. 判斷「是否需要回覆」：沒有新問題、已完整答覆、單純按讚／表情、重複訊息可不回；不可為提高互動而硬回。
5. 回覆前以最新正式產品資料及包裝為依據，確認商品名稱、規格、來源、交期與對外公開狀態。未知價格、庫存、個別訂單狀態、合作條件不得猜測。
6. 生成簡短、自然、繁體中文、符合仙加味語氣的脈絡式回覆；不重複貼 LINE 連結或重複介紹先前已回答內容。
7. 檢查品牌與法規：對外只稱「仙加味」，不得宣稱療效，不公開個資、內部成本或未確認資訊。
8. 發送前再次查詢留言及回覆狀態，避免人工已回覆後 AI 重複發送；記錄唯一 idempotency key（平台＋帳號＋留言 ID＋對話版本）。
9. 平台 API 回傳成功並取得回覆 ID 才標記已回覆；失敗不得假裝成功或盲目重試。

## 自動回覆分級
- **低風險可自動回覆（啟用前仍須通過真實端到端測試）**：簡單致謝、明確且資料可驗證的產品規格／品牌資訊、可核實的官方聯絡入口。
- **先轉人工，不自動發送**：客訴、退款、訂單異常、付款、合作條件、批發價格、醫療／疾病相關問題、資料矛盾、語意不清、對方情緒強烈、任何 AI 無法確定的內容。
- **不回覆**：沒有需要回答的表情／按讚、已回覆且無新問題、可疑洗版；不得自動刪除正常客戶留言。

## 必要驗收案例
- 客戶先問「怎麼喝」，品牌回答後再問「可以加熱嗎」：只回答新問題，先確認實際商品，不重複原回答。
- 品牌已人工回覆：AI 不再重複回覆。
- 同一留言 webhook 重送兩次：最多成功發送一次。
- 客戶僅回「謝謝」或表情：依脈絡決定簡短致意或不回，不機械回覆。
- 價格、退換貨、疾病療效、客訴：正確轉人工。
- API 權限失效、逾時、限流：保留待處理與錯誤紀錄，不亂重試。
- 不同貼文／不同客戶：不得交叉使用對話或個資。
- 三平台各自取得真實回覆回執，且無重複回覆，才可宣稱對應平台啟用。

## 部署守門
- 正式憑證只存 n8n Credentials／受保護環境變數，不得寫入 GitHub。
- 先唯讀盤點，再建立「建議回覆但不送出」測試模式；確認品質與權限後才開啟低風險自動回覆。
- 每次回覆保留來源、分類、依據、決策、發送結果與人工接手狀態；提供人工停止開關。
- 不得覆蓋既有正常的 LINE OA、ERP、Metricool 排程或 n8n 監控。
- 貼文頻率原則每週一／三／五 10:00；排程實際狀態以 Metricool 即時查詢為準，不以過期候選 JSON 為準。
