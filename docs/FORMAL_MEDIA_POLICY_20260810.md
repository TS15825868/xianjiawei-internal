# 仙加味貼文中心正式媒體與守門規則｜目前權威

本文件為貼文中心、500篇母庫、圖文審核、重新生成與部署守門員的目前權威原則。後續若使用者提供更新的正式資料、文案或核准素材，應同步更新能力與資料守門，不得以舊版號、舊固定文案、舊 ZIP 名稱或歷史候選數阻擋正確新版。

## 正式產品規格
- 龜鹿膏：100g／罐
- 龜鹿飲30cc：30cc／罐（小玻璃罐、裸罐、無貼紙）
- 龜鹿飲180cc：180cc／包（鋁袋）
- 龜鹿湯塊：75g／盒｜8塊裝｜每塊約9.375g
- 龜鹿膠：600g （1斤）／盒｜32塊裝｜每塊約18.75 g
- 鹿茸粉：75g／罐

## 正式配圖來源順序
1. **產品／試喝文案**：先使用目前仍符合正式規格的核准產品媒體／試喝圖；產品本體識別始終以 products-v3 真實原圖為不可取代的權威。
2. **30cc 特別規則**：目前 `guilu-drink-30cc.webp` DM 內嵌文字仍寫「30cc／瓶」，與正式「30cc／罐（小玻璃罐）」衝突，因此隔離，不得作為顧客端或貼文正式配圖。30cc 先使用 products-v3 小玻璃裸罐正式原圖＋正確文字。
3. **生活情境文案**：使用者目前最新提供的 ZIP 為 `新貼文的圖(3).zip`，共21個原始檔、20張唯一圖片；其中生活情境候選必須語意匹配後才能使用，產品卡型圖片不因位於 ZIP 就取得產品權威。
4. ZIP 候選必須依文案實際比對季節、情境、環境、冷熱、表情、動作、道具與產品脈絡；只有來源是 ZIP 不代表圖片符合。
5. 配圖有三種正式狀態：
   - `approved_existing`：已有符合且可載入的正式圖，可套用後回待審核。
   - `needs_binary_sync`：有符合文案的 ZIP 原圖，但公開二進位尚未同步；此時保留來源等待同步，**不得亂換圖，也不得因尚未同步就重生成**。
   - `regenerate_if_missing`：正式產品／試喝媒體與 ZIP 都真的沒有符合文案的來源時，才進重新生成。
6. 任何套圖、換圖、文案修改或重新生成後都必須讓舊核准失效，回 `pending_review`，重新完成16項審核；不得自動核准、排程或發布。
7. 產品本體只能使用正式原圖，AI 不得重畫產品；30cc 小玻璃裸罐、180cc 狹長鋁袋與實際產品比例為硬規格。
8. 官網／貼文用小老闆與 LINE OA 專用角色圖分流，正式貼文候選不得直接混用 `/images/brand/line-oa/` 角色素材。

## 重新生成閉環
- 圖不符合／文案不符合／全部重新生成都必須先撤銷舊核准與舊排程。
- 回填或上傳新內容後狀態回 `pending_review`。
- 不得自動核准、排程或發布。
- 需重生成內容不得沿用舊錯圖。
- 已發布內容維持鎖定；立即發布不受固定排程時段限制，但仍需有效16項審核與平台可用狀態。
- 沒有合格來源才進重新生成；「合格來源存在但原圖待同步」不等於缺圖。

## 500篇母庫
- `content/public-post-library.json` 是核心母本，不等於完整500篇；正式500篇由現行相容資料層組裝後再驗收。
- 正式匯出必須確認剛好500篇、ID唯一、products-v3權威、products-v2／舊DM不得回流、需重生成貼文已清空舊圖。
- 已發布／防重發內容與 campaign hold 保持保護，不因重新同步母庫而被建立第二份。
- 目前資產庫標成 `deprecated-reference-only`、`preflight-rejected-reference-only`、`superseded-reference-only` 的素材不得再成為未發布貼文的新候選。
- 不得再以「某歷史 layer 幾篇」「至少121篇重生成」「固定安全重用幾篇」等歷史數字當 release gate。

## 守門原則
- 驗能力、正式資料、圖像權威、真實二進位與安全閉環，**不驗舊版固定句子**。
- UI runtime、post-bank、Rich Menu、媒體 cache 等可以正常升版，不得因版本號本身失敗。
- 使用者更新正式資料或核准圖後，守門員必須同步採用新資料；不得拿已退役規格或舊文案反向阻擋新版。
- 必須硬擋：products-v2、產品 AI 重畫、30cc/180cc 外觀錯誤、30cc「瓶」舊稱、圖文錯配、拼貼、裁切、官網／LINE OA角色素材混用、假圖片／本機路徑冒充圖片、跳過16項審核、修改後沿用舊核准。
