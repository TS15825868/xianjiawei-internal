# 仙加味獲客／跟進智慧層 v2

日期：2026-09-16

## 目的

把外部公開的 AI 獲客與陌生開發概念，轉成仙加味自己的內部客戶整理、分級、跟進、優先排序與提醒能力。不是課程，也不複製外部品牌、文案、圖片或版型。

## 已驗證的外部 benchmark 重點

目前公開頁面可直接確認的核心做法為：

1. AI 精準找客：利用 AI 找出理想客戶，避免大海撈針。
2. AI 自動撰寫開發訊息：協助產生較適合陌生開發的訊息。
3. 24 小時「自動進人」系統：讓名單持續進入開發流程。
4. 持續跟進到成交：流程從精準找客、自動開發、持續跟進延伸到成交。

公開頁面沒有明確列出所使用的具體 AI 工具名稱，因此仙加味只吸收上述流程概念，不把未公開的工具或技術細節當成既定事實。

## 仙加味轉換方式

外部 benchmark 不直接照抄，轉成仙加味自己的四層能力：

- 精準找客 → B2B／B2C 客戶類型、來源、來源細分、關注產品、意向程度與開發優先分數。
- 開發訊息 → 依客戶類型與已知需求提供合規「建議聯絡文字」，只複製到剪貼簿，由人工確認後自行發送。
- 自動進人 → 官網、LINE OA、社群與實體接觸的來源未來統一回到客戶資料，不另建第二套 CRM。
- 持續跟進 → 客戶階段、上次聯絡、下次跟進、下一步、負責人與 ERP 任務提醒。

## 現行架構

沿用既有 ERP 與 Cloudflare D1，不建立第二套 CRM。真實客戶姓名、電話、地址、Email、拜訪與聯絡內容只存 D1，不存 GitHub。

正式前端智慧層：`assets/js/growth-intelligence.js`

### 客戶新增欄位

- 客戶類型：B2C／B2B／合作夥伴／其他
- 客戶階段：新名單／了解中／已聯絡／持續跟進／試喝或樣品／已成交／回購／暫緩
- 意向程度：低／中／高
- 偏好聯絡方式
- 來源細分
- 關注產品
- 上次聯絡日期
- 下次跟進日期
- 下一步
- 標籤
- 負責人
- 聯絡限制：可正常聯絡／只回覆主動詢問／停止主動聯絡

### 營運總覽

顯示：

- 今天以前待跟進
- 高意向未成交
- B2B 開發中
- 優先跟進名單

### B2B 開發優先分數

系統目前依既有客戶資料做透明、可解釋的內部排序，考量：

- 是否為 B2B
- 意向程度
- 是否已有關注產品
- 來源細分是否完整
- 是否已有偏好聯絡方式
- 是否有電話或 Email
- 目前客戶階段
- 是否已設定下次跟進日期
- 跟進是否已到期

分數只代表「工作優先順序」，不代表成交機率，也不得拿來對外宣稱 AI 預測成交。

### 任務與建議文字

- 到期客戶可一鍵建立 ERP 跟進任務。
- 任務使用客戶 ID＋跟進日期建立防重複標記，同一客戶同一日期不重複建立未完成任務。
- B2B／B2C 可產生不含療效宣稱的建議聯絡文字。
- 建議文字只複製到剪貼簿，不會自動送出。
- `reply_only` 與 `do_not_contact` 不列入主動跟進；不得產生主動開發訊息或跟進任務。

## LINE OA 現況對照

目前 LINE OA 已具備產品、價格、推薦、人工客服、試喝與下單流程；正式訂單／試喝完成後會寫入既有 CRM。現階段缺口是：一般高意向互動（例如價格、推薦、人工客服、產品比較）尚未回到正式 ERP 的客戶階段與跟進資料。

目前 Cloudflare Access 的人員登入驗證要求有效 Access JWT 與 ERP profile email。LINE OA 是伺服器對伺服器服務，不能冒充人員登入，也不得為了串資料開放未驗證 API。

依 Cloudflare 官方現行做法，後續應使用 Access Service Token／Service Auth 類型的機器身分路徑，Client ID／Client Secret 必須保存於部署環境秘密變數，不得寫入 GitHub。建立正式機器身分與 Access policy 前，不直接啟用 LINE→D1 高意向事件寫入。

## 安全與品牌原則

1. AI／智慧層協助整理、分級、提示下一步、優先排序與提醒，不自動大量群發陌生訊息。
2. `reply_only` 只允許回覆對方主動詢問；`do_not_contact` 停止主動聯絡。
3. 對外內容仍完全遵守仙加味最新品牌、產品、圖片與台灣相關廣告法規。
4. 外部資料只學方法與結構；未經確認的外部功能不得寫成既定事實。
5. 新版正確資料優先於舊規則，但不能因系統進化破壞現有客戶、拜訪、訂單與貼文功能。
6. 不為了自動化而繞過 Cloudflare Access、公開客戶資料或把私密 Token 寫入 GitHub。
7. 不新增與既有 `growth-intelligence` 重複的第二套 acquisition／CRM 頁面或資料層。
